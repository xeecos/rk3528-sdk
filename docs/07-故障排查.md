# 07 · 故障排查

先做三件事，多数问题能直接定位：

```bash
./rk3528-sdk.sh status                      # 看源码/工具链/产物是否齐全
./rk3528-sdk.sh config                      # 看生效路径是否被改错
tail -100 logs/<最近的日志>.log              # 看真正的报错
```

调试脚本本身：`RK_DEBUG=1 ./rk3528-sdk.sh <命令>` 会在失败时打印行号与命令。
预演：`./rk3528-sdk.sh --dry-run <命令>` 可检查「将要执行什么」。

---

## 1. 环境 / 依赖

| 现象 | 原因与处理 |
|---|---|
| `当前不是受支持的 Linux 环境` | 在 Windows 原生 Git Bash / MSYS2 里跑了。请用 WSL2（见 [09-WSL2构建指南.md](09-WSL2构建指南.md)）；只想看命令可用 `RK_ALLOW_NON_LINUX=1 RK_DRY_RUN=1` 预演 |
| `检测到 WSL1` | `check-host` 拒绝 WSL1。管理员 PowerShell 执行 `wsl --set-version <发行版名> 2` 后重启 WSL |
| `RK_WORKSPACE ... 位于 drvfs` | WSL2 下把源码放到了 `/mnt/*`。执行 `cp config/sdk.wsl.conf.example config/sdk.local.conf` 改到 ext4 |
| `请勿用 root 运行编译` | OpenWrt 与 sd-fuse 都拒绝 root。换普通用户；仅 `check-host --install`、`install-toolchain`、`fusing.sh`、`dd` 需要 sudo |
| `Ubuntu 18.04 ... 不支持` | 官方要求 20.04+（缺 `lz4`）。升级系统 |
| `缺少命令 'xxx'` | `./rk3528-sdk.sh check-host --install`；非 apt 系统手工装等价包 |
| `mkimage: not found` / `dtc: not found` | 装 `u-boot-tools` / `device-tree-compiler` |
| `depmod: command not found` | 装 `kmod`；脚本也会尝试 `/sbin/depmod` |
| `menuconfig` 打不开或界面错乱 | 装 `libncurses-dev`，使用真实终端（不要在日志重定向/管道中运行）；本工具的 `menuconfig` 特意不走 tee |
| `磁盘空间不足` | 把 `RK_WORKSPACE` / `RK_DOWNLOAD_DIR` 指向大盘，或调低 `RK_MIN_FREE_GB`（仅影响检查阈值，不解决真实空间不足） |
| 编译到一半进程被杀 | 内存不足（OOM）。减 `RK_JOBS`、加 swap；打包 rootfs 尤其吃内存 |

## 2. 网络 / 下载

| 现象 | 处理 |
|---|---|
| `git clone` 超时 / GitHub 连不上 | 设 `RK_GITHUB_MIRROR=https://ghproxy.net/https://github.com`；`RK_RAW_MIRROR=https://ghproxy.net/` 用于 raw 文件 |
| `repo sync` 中断 | **直接重跑 `fw-init`**，检测到 `.repo` 会跳过 init 只续传 sync |
| 分区镜像下载失败 | 从网盘 `03_分区镜像文件` 下载 tgz，用 `sdfuse-init <OS> --images /path/to/xxx-images.tgz` |
| `mkkrnlimg 不是 ELF 可执行文件` | 下载到 HTML 错误页了。删掉 `downloads/tools/` 下对应文件，配置 `RK_RAW_MIRROR` 后重跑 `kernel-build --pack-only` |
| prebuilts clone 太大 | 从网盘单独下 `toolchain-11.3-aarch64.tar.xz`，用 `install-toolchain --package FILE` |
| 工具链解压后找不到 gcc | 检查 `/opt/FriendlyARM/toolchain/` 下实际目录名，设置 `RK_TOOLCHAIN_VERSION` 或直接 `RK_TOOLCHAIN_BIN` |

## 3. FriendlyWrt（路线 A）

| 现象 | 处理 |
|---|---|
| `no .current_config.mk, please select a board first.` | 先跑 `fw-build all`（或 `docker`）选一次板型，再执行 `sd-img` 等增量目标 |
| 首次编译随机报错 | 按 WiKi 用单线程定位：`fw-build single`（`make -j1 V=s`）；docker 版 `fw-build single --docker` 会先清 `tmp/go-build` |
| go 相关编译错误 | docker 版清 `friendlywrt/tmp/go-build` 后重试 |
| `Can't find a build config file` | 传入的 `.mk` 名不对；检查 `device/friendlyelec/` 下实际文件名，或改 `RK_FW_BOARD_MK` |
| `emmc-img` 提示缺 eflasher | `build.sh` 会尝试 `tools/get_rom.sh eflasher` 自动下载；网络不通时手工准备 |
| 改了 menuconfig 但镜像没变化 | 用 `fw-build rebuild`（会询问是否清 `friendlywrt/tmp`），确认时选 Y |
| `cleanall` 太慢 / 把东西删多了 | 它会 `distclean` u-boot、kernel 并 `make clean` friendlywrt；只想删旧镜像用 `fw-build clean` |

## 4. 内核 / U-Boot（路线 B）

| 现象 | 处理 |
|---|---|
| `未找到 aarch64-linux-gnu-gcc` | 跑 `install-toolchain`；或设置 `RK_TOOLCHAIN_BIN` 指向实际 bin 目录 |
| `未找到 rk3528-nanopi*-rev*.dtb` | 内核没编译完 / 分支不对。确认 `RK_KERNEL_BRANCH=nanopi6-v6.1.y`，重跑 `kernel-build` |
| `resource_tool` 打包失败 | 确认 DTB 存在、两张 logo.bmp 已下载；可用 `kernel-build --pack-only` 只重试打包 |
| `depmod` 报 `-w` 或 `Module.symvers` 问题 | 确认在内核源码根目录执行（脚本用 `run_in` 保证），且 `modules_install` 已成功 |
| `xargs aarch64-linux-strip` 报参数为空 | 脚本用 `find -print0 \| xargs -0 -r`，无 .ko 时会跳过；若仍报错说明 `strip` 不在 PATH |
| `./make.sh nanopi_r3` 找不到 rkbin | `rkbin` 必须与 `uboot-rockchip` **同级**。检查 `RK_RKBIN_SRC` / `RK_UBOOT_SRC` |
| U-Boot 没生成 `trust.img` / loader | 部分版本产物合并进 `uboot.img`；脚本会提示，属正常 |
| 刷了 kernel 后驱动异常 / 网卡不工作 | `/lib/modules` 还是旧版本。上传 `kernel-modules-<ver>.tar.gz` 替换后 `depmod -a` + reboot |

## 5. sd-fuse（路线 C）

| 现象 | 处理 |
|---|---|
| `不支持的 OS 名称` | 目录名在脚本内硬编码，不能改名。用 `sdfuse-init` 不带参数时打印的列表核对，或修改 `RK_SDFUSE_OS_LIST` |
| `缺少分区镜像目录` | 先跑 `sdfuse-init <OS>`；用 `--images` 指定本地 tgz |
| `缺少 eflasher 分区镜像` | `sdfuse-init <OS> --with-eflasher` |
| `镜像太大无法打包` | `sdfuse-image sd <OS> --raw-size-mb 16000`（或 `RAW_SIZE_MB=16000`） |
| 脚本一直停下来问 Y/N | 确认 `SDFUSE_NONINTERACTIVE=y`；本工具默认通过 `RK_SDFUSE_NONINTERACTIVE` 导出 |
| 制作 rootfs 后无法启动 | 文件权限被破坏。必须用 `tools/extract-rootfs-tar.sh` 解压、用 `tar -cpzf` 打包 |
| 打包进程中途退出 | 内存不足，加内存/swap |
| 想要 Docker 性能 / 开 Swap | `sdfuse-image sd <OS> --no-overlayfs`（等价于替换 `parameter-plain.txt` 与 `dtbo-plain.img`） |
| `build-kernel.sh` 每次都 distclean 很慢 | `sdfuse-build kernel <OS> --skip-distclean` |
| 只想编译头文件 | `sdfuse-build headers <OS>`（自动设 `MK_HEADERS_DEB=1 BUILD_THIRD_PARTY_DRIVER=0`） |

## 6. 烧录 / 分区

| 现象 | 处理 |
|---|---|
| `xxx 不是块设备` | 设备名写错或没插卡。用 `lsblk` / `diff before.txt after.txt` 确认 |
| `镜像超过分区容量，拒绝写入` | 内核开了太多选项导致 `kernel.img` 超限；精简配置或换用线刷完整固件 |
| `dd` 后不开机 | 用线刷重刷 kernel/resource；或用 `out/partition-backup-*/` 里的备份写回 |
| 分区编号与文档不同 | 一律以 `parted /dev/mmcblk2 print` 实际输出为准；脚本优先按 `PARTLABEL` 名称定位 |
| `upgrade_tool` 找不到设备 | 确认开发板已 `sudo reboot loader`、USB 线是数据线、工具版本 ≥ v2、`upgrade_tool LD` 能看到设备 |
| `upgrade_tool: invalid option` | 用了 v1 版本，换 `upgrade_tool_v2.30_for_linux` 并用 `--tool` 指定 |
| 完全变砖 | 按住 Maskrom 键上电，用 RKDevTool / upgrade_tool 重刷 `MiniLoaderAll.bin` + uboot，再重刷系统 |

### W132D（路线 D）

| 现象 | 处理 |
|---|---|
| `build image 需要 Docker` | 安装并启动 docker（Armbian 框架在容器中跑）；`build flash-tools` 与 `w132d flash` 不需要 |
| Python 版本过低 | 构建需 3.12+、刷写需 3.9+；`w132d init` / `w132d status` 会体检 |
| `out/manifest.json` 缺失 | 先跑 `w132d fetch --download` |
| 完整镜像构建失败 / loop 报错 | 检查 `/dev/loop-control`；WSL2 可 `wsl --shutdown` 后重进，或换原生 Ubuntu |
| 磁盘不足 | 上游要求 ≥ 35 GiB；把 `RK_WORKSPACE` 指向大盘（WSL2 用 ext4） |
| `SHA256SUMS` 无 zip 条目 / 校验失败 | 重新下载，或用 `--tag <固定版本>` 锁定避免 latest 资产变动 |
| 未出现 `FLASH_DRY_RUN_OK` | 刷写包不完整或结构变化，检查 `downloads/w132d-flash/<tag>/` |
| USB 设备识别不到 | 核对 Reset 针孔时序、数据线、只连一台；**WSL2 USB 直通未验证，建议原生 Ubuntu 物理机** |
| 误把 BSP 镜像刷进 W132D | 分区布局不同，不能混刷；重新用 `w132d flash` 完整刷官方包恢复 |

详见 [10-W132D主线Linux.md](10-W132D主线Linux.md)。

## 7. 脚本自身

| 现象 | 处理 |
|---|---|
| `bash: ... : Permission denied` | `chmod +x rk3528-sdk.sh scripts/*.sh`，或统一用 `bash rk3528-sdk.sh ...` |
| `未知命令` | `./rk3528-sdk.sh help` 查看命令表；注意子命令是 `fw-build` 这类带连字符的形式 |
| `--conf` 没生效 | 配置加载顺序见 [01-构建环境.md](01-构建环境.md#5-配置体系)；环境变量优先级最高，检查是否已被 export 覆盖 |
| 预演模式下中途报「目录不存在」 | 已改为只告警；若仍失败，说明是某个直接 `die` 的校验，请把命令与输出提交 issue |
| 想看脚本到底执行了什么 | `RK_DRY_RUN=1` 预演，或 `RK_DEBUG=1` 实跑 |
