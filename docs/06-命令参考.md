# 06 · 命令参考

## 1. 调用形式

```bash
./rk3528-sdk.sh [全局选项] <命令> [子命令/参数...]
```

所有 `scripts/*.sh` 也可独立运行：`bash scripts/fw-build.sh all`，它们会自行加载 `lib/config.sh`。

### 全局选项

| 选项 | 环境变量 | 作用 |
|---|---|---|
| `--dry-run` | `RK_DRY_RUN=1` | 只打印命令，不下载/不编译/不写入 |
| `--yes` / `-y` | `RK_ASSUME_YES=1` | 跳过普通交互确认；**危险操作仍需手工输入确认串** |
| `--conf FILE` | `RK_CONF=FILE` | 追加一份配置文件（最高优先级） |
| `-h` / `--help` / `help` | — | 显示帮助 |

## 2. 命令总表

### 环境准备

| 命令 | 参数 | 说明 |
|---|---|---|
| `check-host` | `[--install]` | 检查系统/依赖/磁盘/工具链；`--install` 用 apt 安装依赖 |
| `install-toolchain` | `[--package FILE] [--force]` | 安装 11.3-aarch64；`--package` 用本地 tar.xz，`RK_TOOLCHAIN_URL` 可直接下载 |
| `config` | — | 打印生效配置 |
| `status` | — | 打印配置 + 各源码目录/工具链状态 + 已有产物 |
| `clean` | `[images\|logs\|all] [--yes]` | 清理 `out/` 产物与 `logs/` 日志，不动 `workspace/` |

### 路线 A：FriendlyWrt

| 命令 | 参数 | 实际动作 |
|---|---|---|
| `fw-init` | `[--force] [--branch B] [--manifest M] [--jobs N]` | clone repo 工具 → `repo init -u ... -b B -m M` → `repo sync -c --no-clone-bundle -jN` |
| `fw-build all` | — | `./build.sh rk3528.mk` |
| `fw-build docker` | — | `./build.sh rk3528-docker.mk` |
| `fw-build uboot\|kernel\|friendlywrt` | — | `./build.sh <target>` |
| `fw-build sd-img\|emmc-img` | — | `./build.sh <target>` |
| `fw-build menuconfig` | — | `(cd friendlywrt && make menuconfig)` |
| `fw-build rebuild` | — | 确认后清 `friendlywrt/tmp` → `make -jN` → `sd-img` → `emmc-img` |
| `fw-build single` | `[--docker]` | `make -j1 V=s`；`--docker` 时先 `rm -rf tmp/go-build` |
| `fw-build clean\|cleanall` | — | `./build.sh clean / cleanall` |
| `fw-build` 通用 | `[--no-log]` | 关闭 tee 日志（默认写到 `logs/`） |

### 路线 B：手工编译

| 命令 | 参数 | 说明 |
|---|---|---|
| `kernel-build` | `[--friendlywrt] [--menuconfig] [--pack-only] [--defconfig NAME] [--jobs N] [--no-clone]` | 编译内核、模块，打包 `kernel.img` / `resource.img` |
| `uboot-build` | `[--no-clone] [--board NAME]` | `./make.sh nanopi_r3`，收集 uboot/trust/MiniLoaderAll.bin |

`kernel-build` 参数细节：

- `--friendlywrt`：加载 `nanopi5_linux_defconfig` + `friendlywrt.config`
- `--menuconfig`：defconfig 后打开交互配置界面
- `--defconfig NAME`：自定义 defconfig（对应 sd-fuse 的 `KCFG`）
- `--pack-only`：跳过编译，只用现有 `arch/arm64/boot/Image` 与 DTB 重新打包
- `--no-clone`：使用 `RK_KERNEL_SRC` 下已有源码

### 路线 C：sd-fuse

| 命令 | 参数 | 说明 |
|---|---|---|
| `sdfuse-init [OS]` | `[--images FILE\|URL] [--with-eflasher] [--force] [--os NAME]` | clone sd-fuse、下载解压 `*-images.tgz`；`--with-eflasher` 额外准备 eflasher |
| `sdfuse-build kernel [OS]` | `[--kcfg NAME] [--no-clone] [--no-third-party] [--skip-distclean]` | `KERNEL_SRC=... ./build-kernel.sh <OS>` |
| `sdfuse-build headers [OS]` | 同上 | `MK_HEADERS_DEB=1 BUILD_THIRD_PARTY_DRIVER=0 ...` |
| `sdfuse-build uboot [OS]` | `[--no-clone]` | `UBOOT_SRC=... ./build-uboot.sh <OS>` |
| `sdfuse-image sd [OS]` | `[--raw-size-mb N] [--no-overlayfs] [--no-collect]` | `./mk-sd-image.sh <OS>` |
| `sdfuse-image emmc [OS]` | 同上 | `./mk-emmc-image.sh <OS> autostart=yes`（需 eflasher 目录） |
| `sdfuse-image fuse [OS]` | `--device /dev/sdX` | `sudo ./fusing.sh /dev/sdX <OS>`（高危） |

### 烧录与更新

| 命令 | 参数 | 说明 |
|---|---|---|
| `install-board` | `--device DEV [--kernel F] [--resource F] [--uboot F] [--trust F] [--img-dir DIR] [--execute] [--no-backup]` | 在**开发板**上 dd 更新 GPT 分区 |
| `flash-loader` | `[--kernel F] [--resource F] [--uboot F] [--img-dir DIR] [--tool PATH] [--execute] [--no-reboot]` | 主机线刷；开发板需先 `sudo reboot loader` |

`install-board` / `flash-loader` 省略文件参数时会自动到 `out/manual-kernel/`、`out/manual-uboot/` 或 `--img-dir` 寻找。
**两者默认只打印计划**，加 `--execute` 才实际写入。
⚠️ 这两条命令**不适用于 W132D**（分区布局与刷写协议不同）。

### 路线 D：W132D 主线 Linux

统一形式：`./rk3528-sdk.sh w132d <动作> [参数]`，完整说明见 [10-W132D主线Linux.md](10-W132D主线Linux.md)。

| 动作 | 参数 | 说明 |
|---|---|---|
| `w132d init` | `[--ref REF] [--check-only]` | clone 上游 + 环境体检（Docker / Python / loop / 磁盘） |
| `w132d fetch` | `[--latest] [--channel stable\|experimental] [--detect] [--download] [--no-download]` | 锁定并下载上游来源 → `out/manifest.json` |
| `w132d build` | `[kernel\|image\|uboot\|bsp\|flash-tools\|fnos] [--framework PATH] [--output DIR] [--base-image F] [--base-sha256 HEX]` | 默认 `kernel`；`image` 出完整 `w132d.img` |
| `w132d verify` | `<static\|tests\|patches\|debs\|image\|candidate> [--jobs N] [--directory D] [--image F] [--full] [--docker]` | 与 CI 一致的检查 |
| `w132d flash` | `[--tag TAG] [--execute] [--verify-only]` | 下载 Release 刷写包 + SHA256 校验 + 只读自检；`--execute` 才刷写 |
| `w132d status` | — | 上游提交、manifest 版本、产物、刷写包、依赖状态 |
| `w132d help` | — | 显示该路线帮助 |

`w132d flash` 默认不访问 USB；`--execute` 需输入 `FLASH` 确认串，`--verify-only` 需输入 `VERIFY`。
该路线与 A/B/C **完全隔离**，产物与刷写工具互不通用。

| 变量 | 默认 | 说明 |

| `RK_DRY_RUN` | `0` | `1` = 预演 |

## 5. 退出码

脚本统一 `set -euo pipefail`：命令失败立即以非 0 退出，`run_in_logged` 通过 `pipefail` 保证 `tee` 不掩盖失败。
`confirm` 被拒绝时打印「已取消」并退出 1。
