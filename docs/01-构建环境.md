# 01 · 构建环境

## 1. 主机要求

**本仓库只支持两个平台**（见根 README 的支持矩阵）：

| 平台 | 版本 |
|---|---|
| 原生 Ubuntu **x86_64** | 20.04 / 22.04 / 24.04 |
| Windows 11 **WSL2** 中的 Ubuntu | 22.04（24.04 亦可），完整步骤见 [09-WSL2构建指南.md](09-WSL2构建指南.md) |

两者共用同一套 x86_64 Linux 用户态与官方预编译 ELF，因此依赖清单完全一致。
`WSL1`、`macOS`、`arm64 主机`、其它发行版、Ubuntu 18.04 均**不作为支持目标**：
`check-host` 会拒绝 WSL1 与 18.04，其余只给警告、不修兼容问题。

| 项目 | 要求 | 说明 |
|---|---|---|
| CPU 架构 | **x86_64** | 两个受支持平台一致，无需架构分支 |
| 操作系统 | Ubuntu 20.04 / 22.04 / 24.04 | **18.04 会失败**（缺 `lz4`）；WSL2 内同样用 Ubuntu |
| 内存 | ≥ 8 GB，推荐 12~16 GB | 内存不足时打包 rootfs 的进程会被 OOM killer 杀掉 |
| 磁盘 | 全量 FriendlyWrt ≥ 60 GB，仅内核 ≥ 20 GB | 每个源码仓库、out、dl 都会占空间 |
| 用户 | 普通用户 + `sudo` 权限 | **不要用 root 编译**：OpenWrt 与 sd-fuse 均拒绝 root 运行 |
| 网络 | GitHub + `downloads.friendlyelec.com` | 首次同步源码与分区镜像需要数十 GB 流量 |

脚本用 `./rk3528-sdk.sh check-host` 检查平台、系统版本、架构、依赖命令、磁盘空间与工具链，
WSL2 下还会额外核对工作区是否在 drvfs 上、loop 设备是否可用。

> **Windows 用户**：不要用原生 Git Bash / MSYS2，也不要用 WSL1。装好 WSL2 后先执行
> `cp config/sdk.wsl.conf.example config/sdk.local.conf`，让源码、下载、产物落在 WSL2 原生
> ext4（`/home/...`）而不是 `/mnt/*`——drvfs 不保留 Linux 权限与设备节点，会导致 ext4
> rootfs 镜像损坏，且海量小文件 IO 慢数倍。

## 2. 依赖包

`./rk3528-sdk.sh check-host --install` 会执行 `apt-get update` 并安装以下包（一次性安装，失败时自动回退逐包安装并列出失败项）：

```text
基础工具    git curl wget ca-certificates make gcc g++ build-essential file
            tar xz-utils gzip bzip2 unzip zip p7zip-full rsync sudo kmod binutils
内核/镜像   cpio squashfs-tools dosfstools e2fsprogs exfatprogs parted lz4 u-boot-tools
            device-tree-compiler libncurses-dev libssl-dev libelf-dev zlib1g-dev
            flex bison gawk gettext patch bc
OpenWrt     python3 python3-setuptools libglib2.0-dev subversion texinfo xmlto
            libtool autoconf automake pkg-config ninja-build cmake
            qemu-utils util-linux
x86_64 追加 lib32gcc-s1 libc6-dev-i386 gcc-multilib g++-multilib
```

关键依赖的用途：

| 包 | 用途 |
|---|---|
| `lz4` | 内核 / 镜像压缩，18.04 缺失会导致 sd-fuse 失败 |
| `u-boot-tools` | `mkimage`，打包 `boot.img` |
| `device-tree-compiler` | `dtc`，编译 DTB |
| `squashfs-tools` | 制作 OpenWrt squashfs 根文件系统 |
| `libncurses-dev` | `make menuconfig` |
| `python3` / `setuptools` | repo 工具与 OpenWrt 构建脚本 |
| `kmod` | `depmod`，生成模块依赖 |
| `parted` / `lsblk` | 查看 GPT 分区布局、核对烧录目标 |
| `exfatprogs` | `mkfs.exfat`，打 eMMC 卡刷固件（`mk-sd-image.sh eflasher` 分支）时需要，WSL2 上尤其容易漏装 |

非 apt 发行版请手工安装等价包，`check-host` 会逐项报告 `[缺失]`。

## 3. 交叉编译工具链

WiKi 指定 `11.3-aarch64`，路径 `/opt/FriendlyARM/toolchain/11.3-aarch64/bin/`：

```bash
export PATH=/opt/FriendlyARM/toolchain/11.3-aarch64/bin/:$PATH
export CROSS_COMPILE=aarch64-linux-gnu-
export ARCH=arm64
```

本工具的 `kernel-build` / `uboot-build` 会自动设置上述变量（见 `lib/config.sh` 的 `setup_toolchain_path`）。

### 安装方式一（官方，脚本默认）

```bash
./rk3528-sdk.sh install-toolchain
```

等价于官方 README：

```bash
git clone https://github.com/friendlyarm/prebuilts.git -b master --depth 1
cd prebuilts/gcc-x64
sudo tar xf toolchain-11.3-aarch64.tar.xz -C /
```

### 安装方式二（网盘单独下载，节省带宽）

`prebuilts` 仓库含多套工具链，clone 可能要数 GB。可从 FriendlyELEC 网盘下载单个 `toolchain-11.3-aarch64.tar.xz` 后：

```bash
./rk3528-sdk.sh install-toolchain --package /path/to/toolchain-11.3-aarch64.tar.xz
```

或直接给 URL：

```bash
RK_TOOLCHAIN_URL=https://example.com/toolchain-11.3-aarch64.tar.xz \
  ./rk3528-sdk.sh install-toolchain
```

### 自定义位置

工具链不在标准路径时，在 `config/sdk.local.conf` 中设置：

```bash
RK_TOOLCHAIN_ROOT=/opt/mytoolchains
RK_TOOLCHAIN_VERSION=11.3-aarch64
# 或直接指定 bin 目录
RK_TOOLCHAIN_BIN=/opt/mytoolchains/11.3-aarch64/bin
RK_CROSS_COMPILE=aarch64-linux-gnu-
```

验证：`./rk3528-sdk.sh status` 应显示 `[存在]` 且能打印 gcc 版本。

> 路线 A（FriendlyWrt 全量工程）**不需要**这套系统级工具链 —— manifest 里自带 `toolchain/`（prebuilts）项目，`build.sh` 会调用 `install_toolchain` 自行处理。

## 4. 目录与容量规划

默认布局：

```text
rk3528-sdk/
├── workspace/                       源码（最大，数十 GB）
│   ├── friendlywrt25-rk3528/        FriendlyWrt repo 工程
│   ├── sd-fuse_rk3528/              sd-fuse + 各 OS 分区镜像目录
│   ├── kernel-rockchip/            内核源码（路线 B/C 共用）
│   ├── uboot-rockchip/ / rkbin/    U-Boot 源码（两者必须同级）
│   └── prebuilts/                  工具链压缩包（仅安装时需要）
├── downloads/                       分区镜像 tgz、mkkrnlimg、resource_tool、logo.bmp
├── out/                             产物：kernel.img、镜像、模块包、分区备份
└── logs/                            构建日志（tee 输出）
```

这四个目录内的实际内容均被 `.gitignore` 忽略，只有各自的 `README.md` 作为占位文档入库
（Git 不追踪空目录，加入 README 才能把目录结构提交到仓库）。目录内容可安全清空重建，
**不要**在编译中途删，也**不要**删掉这些 README.md。

推荐把大目录挂到独立磁盘：

```bash
# config/sdk.local.conf
RK_WORKSPACE=/mnt/data/rk3528/workspace
RK_DOWNLOAD_DIR=/mnt/data/rk3528/downloads
RK_OUTPUT_DIR=/mnt/data/rk3528/out
RK_LOG_DIR=/mnt/data/rk3528/logs
```

`check_free_gb` 会在编译前用 `df` 检查；阈值由 `RK_MIN_FREE_GB`（默认 50）控制，空间不足会给出警告或中止。

## 5. 配置体系

加载顺序（后者优先级更高）：

1. `config/sdk.conf` —— 仓库默认（所有上游 URL、分支、OS 列表）
2. `config/sdk.local.conf` —— 本机私有配置（已 gitignore）
3. `$RK_CONF` 指向的文件 —— 临时/多套配置
4. **同名环境变量** —— 最高优先级

配置项里的 URL / 分支 / OS 列表全部可改，例如切换到 Gitee 镜像或自建镜像：

```bash
RK_GITHUB_MIRROR=https://ghproxy.net/https://github.com \
RK_RAW_MIRROR=https://ghproxy.net/ \
  ./rk3528-sdk.sh sdfuse-init ubuntu-noble-core-arm64
```

常用变量一览表见 [06-命令参考.md](06-命令参考.md#环境变量)。

查看生效值：

```bash
./rk3528-sdk.sh config
./rk3528-sdk.sh status
```

## 6. 网络与镜像

| 资源 | 默认地址 | 可配置项 |
|---|---|---|
| 内核源码 | `github.com/friendlyarm/kernel-rockchip` `nanopi6-v6.1.y` | `RK_KERNEL_REPO` / `RK_KERNEL_BRANCH` |
| U-Boot 源码 | `github.com/friendlyarm/uboot-rockchip` `nanopi5-v2017.09` | `RK_UBOOT_REPO` / `RK_UBOOT_BRANCH` |
| rkbin | `github.com/friendlyarm/rkbin` `friendlyelec` | `RK_RKBIN_REPO` / `RK_RKBIN_BRANCH` |
| sd-fuse | `github.com/friendlyarm/sd-fuse_rk3528` `kernel-6.1.y` | `RK_SDFUSE_REPO` / `RK_SDFUSE_BRANCH` |
| FriendlyWrt manifest | `github.com/friendlyarm/friendlywrt_manifests` `master-v25.12` | `RK_FW_MANIFEST_URL` / `RK_FW_MANIFEST_BRANCH` |
| 分区镜像 | `downloads.friendlyelec.com/os-images/rk3528/images` | `RK_IMAGES_BASE_URL` |
| 文件系统包 | `downloads.friendlyelec.com/rootfs/rk3528` | `RK_ROOTFS_BASE_URL` |
| 打包小工具 | `raw.githubusercontent.com/.../kernel-6.1.y` | `RK_RAW_BASE_URL` / `RK_RAW_MIRROR` |

`git_clone` 与 `download` 都支持断点/重试：`curl --retry 3`，`repo sync` 可直接重跑续传，`git_clone` 遇到已存在目录默认跳过（`RK_GIT_UPDATE=1` 可强制 fetch + reset）。

> 注意：`RK_RKBIN_BRANCH` 默认 `friendlyelec`（WiKi 手工编译章节），而 FriendlyWrt 的 `rk3528.xml` manifest 中 rkbin 用的是 `nanopi5` 分支。两条路线各用各的，互不干扰。

## 7. 预演与日志

```bash
RK_DRY_RUN=1 ./rk3528-sdk.sh fw-build all        # 或 --dry-run
RK_ASSUME_YES=1 ./rk3528-sdk.sh sdfuse-init      # 或 --yes，跳过普通确认
```

- 预演模式不创建目录、不下载、不编译、不写入；危险确认与工具链/磁盘硬性检查会自动降级为警告，方便完整走一遍流程。
- 所有耗时构建（FriendlyWrt、内核、sd-fuse）通过 `tee` 同步写入 `logs/*.log`。
- 调试脚本本身：`RK_DEBUG=1` 会在 ERR 时打印失败行号与命令。
