# 05 · 烧录、分区更新与恢复

> ⚠️ **高危章节**。`dd`、`fusing.sh`、`upgrade_tool` 都会直接覆写块设备，写错设备会造成不可逆的数据丢失。
> 本工具对所有这类操作默认**只打印计划**，必须显式 `--execute` / `fuse` 动作 + 手工输入确认串才会写入。

---

## 1. GPT 分区布局

RK3528 的各 OS 默认采用 **GPT 分区**，因此可以直接用 `dd` 把分区镜像写到对应分区。

设备节点：

| 介质 | 设备节点 |
|---|---|
| SD / TF 卡（从 SD 启动时） | `/dev/mmcblk0` |
| eMMC | `/dev/mmcblk2` |

在开发板上查看布局：

```bash
parted /dev/mmcblk2 print
```

WiKi 给出的典型输出：

```text
Model: MMC BJTD4R (sd/mmc)
Disk /dev/mmcblk2: 31.3GB
Sector size (logical/physical): 512B/512B
Partition Table: gpt

Number  Start   End     Size    File system  Name      Flags
 1      8389kB  12.6MB  4194kB               uboot
 2      12.6MB  16.8MB  4194kB               trust
 3      16.8MB  21.0MB  4194kB               misc
 4      21.0MB  25.2MB  4194kB               dtbo
 5      25.2MB  41.9MB  16.8MB               resource
 6      41.9MB  83.9MB  41.9MB               kernel
 7      83.9MB  134MB   50.3MB               boot
 8      134MB   2500MB  2366MB  ext4         rootfs
 9      2500MB  31.3GB  28.8GB  ext4         userdata
```

常用分区映射（**以实际 `parted` 输出为准**）：

| 分区号 | Name | 设备节点 (eMMC) | 对应文件 |
|---:|---|---|---|
| 1 | uboot | `/dev/mmcblk2p1` | `uboot.img` |
| 2 | trust | `/dev/mmcblk2p2` | `trust.img` |
| 3 | misc | `/dev/mmcblk2p3` | — |
| 4 | dtbo | `/dev/mmcblk2p4` | `dtbo.img` |
| 5 | resource | `/dev/mmcblk2p5` | `resource.img` |
| 6 | kernel | `/dev/mmcblk2p6` | `kernel.img` |
| 7 | boot | `/dev/mmcblk2p7` | `boot.img` |
| 8 | rootfs | `/dev/mmcblk2p8` | `rootfs.img` |
| 9 | userdata | `/dev/mmcblk2p9` | `userdata.img` |

## 2. 在开发板上用 dd 更新内核 / U-Boot

WiKi 原始命令（更新 eMMC 上的内核）：

```bash
dd if=resource.img of=/dev/mmcblk2p5 bs=1M
dd if=kernel.img  of=/dev/mmcblk2p6 bs=1M
dd if=uboot.img   of=/dev/mmcblk2p1 bs=1M
```

本工具等价且更安全的做法（**在开发板上以 root 执行**）：

```bash
# ① 预演：打印分区布局、要写的文件、目标分区、容量检查
sudo ./rk3528-sdk.sh install-board --device /dev/mmcblk2 \
     --img-dir /abs/path/to/out/manual-kernel

# ② 确认无误后实际写入
sudo ./rk3528-sdk.sh install-board --device /dev/mmcblk2 \
     --img-dir /abs/path/to/out/manual-kernel --execute
```

也可以逐个指定文件：

```bash
sudo ./rk3528-sdk.sh install-board --device /dev/mmcblk0 \
     --kernel /path/kernel.img --resource /path/resource.img \
     --uboot /path/uboot.img --trust /path/trust.img --execute
```

脚本的安全措施：

1. 默认预演，`--execute` 才写入；
2. 先用 `parted <dev> print` / `lsblk` 列出真实布局；
3. **优先按 GPT 分区名**（`PARTLABEL`）定位分区，读不到才回退到 1/2/5/6 默认编号；
4. 校验镜像大小不超过分区容量，超限拒绝写入；
5. 写入前把原分区 `dd` 备份到 `out/partition-backup-<时间戳>/`（`--no-backup` 可关）；
6. 写入前要求手工输入完整设备名（如 `/dev/mmcblk2`）确认；
7. 写完执行 `sync`。

### 更新内核模块

只更新 `kernel.img` 而不同步模块，会导致驱动加载失败。把 `kernel-modules-<ver>.tar.gz` 传到开发板：

```bash
# 在开发板上（先确认目录名与内核版本一致）
sudo mkdir -p /lib/modules
sudo tar xzf kernel-modules-<ver>.tar.gz -C /   # 包内路径为 ./lib/modules/...
sudo depmod -a
sudo reboot
```

或按 WiKi 的说法：把新的驱动模块目录上传并替换 `/lib/modules` 下的文件。

## 3. 线刷（Rockchip upgrade_tool）

适用：开发板还能进系统、或能进 loader/maskrom 模式；需要 USB 线连接主机。

**在开发板上**进入 loader 模式：

```bash
sudo reboot loader
```

**在主机上**确认设备可见（需要 `Linux_Upgrade_Tool` **v2 以上**，WiKi 用 v2.30）：

```bash
upgrade_tool LD
```

WiKi 原始烧写命令：

```bash
sudo upgrade_tool di -k  kernel.img
sudo upgrade_tool di -re resource.img
sudo upgrade_tool di -u  uboot.img
sudo upgrade_tool RD
```

本工具：

```bash
# 预演（打印命令清单、检测设备）
./rk3528-sdk.sh flash-loader --img-dir /abs/path/to/out/manual-kernel

# 实际烧写
sudo ./rk3528-sdk.sh flash-loader --img-dir /abs/path/to/out/manual-kernel --execute
# 指定工具路径：--tool /path/to/upgrade_tool
# 烧完不自动重启：--no-reboot
```

脚本会列出前置检查清单、自动寻找 `upgrade_tool`（PATH 或 `downloads/tools/`）、并在写入前要求输入 `LOADER` 确认串。

> 线刷是**开发板变砖后的主要恢复手段**：即使 SD/eMMC 上的系统起不来，只要能进 Maskrom/Loader 模式就能重刷 uboot 与内核。

## 4. 烧写完整 SD 卡镜像

### 方式一：dd（主机）

```bash
sudo dd if=out/rk3528-sd-ubuntu-noble-core-6.1-arm64-YYYYMMDD.img \
        of=/dev/sdX bs=1M status=progress conv=fsync
sync
```

### 方式二：官方 fusing.sh

```bash
cd workspace/sd-fuse_rk3528
sudo ./fusing.sh /dev/sdX ubuntu-noble-core-arm64
```

本工具封装（会先 `lsblk` 列出块设备，再要求输入设备名确认）：

```bash
./rk3528-sdk.sh sdfuse-image fuse ubuntu-noble-core-arm64 --device /dev/sdX
```

### 查询 SD 卡设备名（官方 README）

```bash
ls -1 /dev > ~/before.txt
# 插入 SD 卡
ls -1 /dev > ~/after.txt
diff ~/before.txt ~/after.txt
```

或 `lsblk -o NAME,SIZE,TYPE,MODEL,MOUNTPOINT`。**务必核对容量与型号**，误写系统盘会毁掉主机数据。

Windows 下可用 balenaEtcher / Win32DiskImager / RKDevTool。

## 5. 打包新的 SD / eMMC 卡刷固件

改完内核或分区镜像后，用 sd-fuse 重新打包（详见[路线 C](04-sd-fuse打包.md)）：

```bash
./rk3528-sdk.sh sdfuse-image sd   <OS>     # SD 启动镜像
./rk3528-sdk.sh sdfuse-image emmc <OS>     # SD-to-eMMC 卡刷镜像（需 eflasher 素材）
```

FriendlyWrt 全量工程则用：

```bash
./rk3528-sdk.sh fw-build sd-img
./rk3528-sdk.sh fw-build emmc-img
```

SD-to-eMMC 卡刷固件（`autostart=yes`）启动后会**自动**把系统装进 eMMC，适合批量生产。

## 6. 出问题时怎么恢复

| 现象 | 处理 |
|---|---|
| 刷完 `kernel.img` 后不开机 | 用线刷重刷 kernel/resource；或用 `install-board` 把备份分区写回 |
| 忘了备份分区 | 重新烧写完整 SD 镜像启动，再从 SD 系统 dd 回 eMMC |
| 完全无法启动、loader 也进不去 | 按住 Maskrom 键上电，用 `upgrade_tool` / RKDevTool 重刷 `MiniLoaderAll.bin` 与 uboot |
| 能开机但驱动异常 | 检查 `/lib/modules` 是否与新内核版本一致，执行 `depmod -a` |
| 分区编号与本文不同 | 一律以 `parted /dev/mmcblk2 print` 的实际输出为准 |

备份文件位置：`out/partition-backup-<时间戳>/{kernel,resource,uboot,trust}.img`，写回方式：

```bash
sudo dd if=out/partition-backup-XXX/kernel.img of=/dev/mmcblk2p6 bs=1M
```
