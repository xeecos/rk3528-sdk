# 00 · 快速开始

本文给出四条最常见的完整操作序列。**只支持原生 Ubuntu 20.04/22.04/24.04 x86_64 与 Windows 11 WSL2 中的 Ubuntu 22.04/24.04**；后者先按 [09-WSL2构建指南.md](09-WSL2构建指南.md) 装好环境并配置 `sdk.local.conf`。

## 前置：准备主机（一次性）

```bash
cd rk3528-sdk
chmod +x rk3528-sdk.sh scripts/*.sh

./rk3528-sdk.sh check-host                 # 先看缺什么
./rk3528-sdk.sh check-host --install       # 用 apt 补齐依赖（需 sudo）
./rk3528-sdk.sh install-toolchain          # 装 11.3-aarch64 到 /opt/FriendlyARM/toolchain
./rk3528-sdk.sh status                     # 确认状态
```

如果主机磁盘紧张，先做容量规划：

```bash
cp config/sdk.local.conf.example config/sdk.local.conf
# 把 RK_WORKSPACE / RK_DOWNLOAD_DIR / RK_OUTPUT_DIR 改到大容量磁盘
./rk3528-sdk.sh config                     # 核对生效路径
```

建议先预演一遍再实跑：

```bash
./rk3528-sdk.sh --dry-run fw-build all     # 只打印命令，不下载不编译
```

## 场景一：从零编译 FriendlyWrt 25.12，得到可烧录的 SD 镜像

```bash
# 1. 拉取多仓库源码（repo init + repo sync，支持中断后重跑续传）
./rk3528-sdk.sh fw-init

# 2. 全量编译：u-boot → kernel → friendlywrt → sd-img
./rk3528-sdk.sh fw-build all

# 3. 追加生成 eMMC 卡刷（eflasher）固件
./rk3528-sdk.sh fw-build emmc-img

# 4. 查看产物
ls -lh workspace/friendlywrt25-rk3528/out/
```

**期望结果**：`out/` 下出现 `rk3528-sd-friendlywrt25-...img(.gz)` 与 eflasher 镜像。
首次编译 1~3 小时，日志在 `logs/fw-build-all-*.log`。

改配置后的增量流程：

```bash
./rk3528-sdk.sh fw-build menuconfig        # 交互改 FriendlyWrt 配置
./rk3528-sdk.sh fw-build rebuild           # rm -rf tmp → make → sd-img → emmc-img
```

编译报错时用单线程定位：

```bash
./rk3528-sdk.sh fw-build single            # make -j1 V=s
./rk3528-sdk.sh fw-build single --docker   # docker 版：先清 tmp/go-build
```

## 场景二：只改内核 / DTB，把新内核刷进已有系统

```bash
# 1. 编译内核（默认 Linux 系统配置）
./rk3528-sdk.sh kernel-build
# FriendlyWrt 系统请改用：./rk3528-sdk.sh kernel-build --friendlywrt
# 需要改内核选项：  ./rk3528-sdk.sh kernel-build --menuconfig

# 2. 产物
ls -lh out/manual-kernel/
#   kernel.img  resource.img  kernel-modules-<版本>.tar.gz

# 3. 在开发板上更新 eMMC 分区（默认预演，确认无误加 --execute）
sudo ./rk3528-sdk.sh install-board --device /dev/mmcblk2 \
     --img-dir /abs/path/to/out/manual-kernel            # 预演
sudo ./rk3528-sdk.sh install-board --device /dev/mmcblk2 \
     --img-dir /abs/path/to/out/manual-kernel --execute  # 实际写入

# 4. 把模块包传到开发板后替换 /lib/modules
```

> 注意 `install-board` 是在**开发板**上运行，所以要把本仓库也放到板上，或至少把 `out/` 产物与 `install-to-board.sh` 拷过去。
> 主机线刷方式见场景三末尾。

## 场景三：定制 Ubuntu Noble 镜像并重新打包

```bash
OS=ubuntu-noble-core-arm64

# 1. 准备 sd-fuse 与官方分区镜像；--with-eflasher 用于后续生成卡刷固件
./rk3528-sdk.sh sdfuse-init "$OS" --with-eflasher

# 2. 按需编译（脚本会自动更新 workspace/sd-fuse_rk3528/$OS/ 下的镜像）
./rk3528-sdk.sh sdfuse-build kernel "$OS"
./rk3528-sdk.sh sdfuse-build headers "$OS"      # 可选：内核头文件 deb
./rk3528-sdk.sh sdfuse-build uboot  "$OS"       # 可选

# 3. 打包
./rk3528-sdk.sh sdfuse-image sd   "$OS"         # SD 启动镜像
./rk3528-sdk.sh sdfuse-image emmc "$OS"         # SD-to-eMMC 卡刷镜像

# 4. 产物（自动复制一份到 out/）
ls -lh out/*.img
```

如果分区镜像包已从网盘下载到本地：

```bash
./rk3528-sdk.sh sdfuse-init "$OS" --images /path/to/03_分区镜像文件/ubuntu-noble-core-arm64-images.tgz
```

烧到 SD 卡（**高危，会抹掉整张卡**）：

```bash
sudo dd if=out/rk3528-sd-ubuntu-noble-core-6.1-arm64-YYYYMMDD.img \
        of=/dev/sdX bs=1M status=progress conv=fsync
# 或
./rk3528-sdk.sh sdfuse-image fuse "$OS" --device /dev/sdX
```

## 常见组合

| 想做的事 | 命令 |
|---|---|
| 只重打 SD 镜像（源码没变） | `fw-build sd-img` 或 `sdfuse-image sd <OS>` |
| 生成用于量产安装到 eMMC 的卡刷固件 | `fw-build emmc-img` / `sdfuse-image emmc <OS>` |
| 内核编译到一半失败，只重打包 kernel.img/resource.img | `kernel-build --pack-only` |
| 禁用 OverlayFS（方便 Docker / Swap） | `sdfuse-image sd <OS> --no-overlayfs` |
| 镜像太大放不下 | `sdfuse-image sd <OS> --raw-size-mb 16000` |
| 只编译内核头文件给第三方驱动用 | `sdfuse-build headers <OS>` |
| U-Boot 改完单独刷 | `uboot-build` → `install-board --uboot ... --execute` |

## 场景四：W132D 主线 Linux（独立体系）

W132D 是同为 RK3528 的中兴云电脑，但走**主线内核 + Armbian**，与前三套 FriendlyELEC 固件**不可混刷**。
完整说明见 [10-W132D主线Linux.md](10-W132D主线Linux.md)。

```bash
# 本地构建（需要 Docker / Python 3.12+ / >= 35 GiB）
./rk3528-sdk.sh w132d init
./rk3528-sdk.sh w132d fetch --download
./rk3528-sdk.sh w132d build image

# 或者跳过构建，直接刷官方 Release（不需要 Docker）
./rk3528-sdk.sh w132d flash                 # 下载 + SHA256 校验 + 只读自检
./rk3528-sdk.sh w132d flash --execute       # 高危：USB 整盘刷写
```

> 刷写用 `rkdeveloptool` 走 USB，不是 `dd` / `upgrade_tool`；WSL2 下 USB 直通未获验证，
> 建议用原生 Ubuntu 物理机执行 `--execute`。
