# 09 · Windows / WSL2 构建指南

**结论：可行，而且这是 Windows 上最推荐的方式。** WSL2 是完整 Linux 内核（轻量 Hyper-V VM），
本仓库的全部脚本在 WSL2 Ubuntu 20.04 / 22.04 / 24.04 里可以直接跑，不需要改代码，也不需要 Docker 或传统虚拟机。
必须用 **WSL2**，WSL1 没有完整 Linux 内核与文件系统语义，不能用。

---

## 1. 磁盘规划（最容易踩的坑）

WSL2 发行版默认把 `ext4.vhdx` 放在 **C 盘** `%LocalAppData%\Packages\...`。
全量编译 FriendlyWrt 需要 60 GB 以上，C 盘空间不够会直接把系统盘撑满。

本机实测可用空间：

| 盘 | 总容量 | 可用 | 建议 |
|---|---:|---:|---|
| C: | 238 GB | 35.8 GB | 系统盘，**不要**让 WSL2 长在这里 |
| D: | 310 GB | 84.8 GB | 备选 |
| E: | 311 GB | 31.5 GB | 项目所在盘，空间偏紧 |
| **F:** | 310 GB | **193.7 GB** | **推荐**，把整个发行版装到这里 |

用官方 `--location` 参数**安装时直接指定位置**，比事后 `--export` / `--import` 迁移省事：

```powershell
# 管理员 PowerShell
New-Item -ItemType Directory -Force F:\WSL
wsl --install -d Ubuntu-22.04 --location F:\WSL\Ubuntu-22.04 --web-download
wsl --set-default-version 2
wsl -l -v          # 确认 VERSION 为 2
```

已经装好的发行版也可以迁移（旧数据会随 tar 一起搬走）：

```powershell
wsl --shutdown
wsl --export Ubuntu-22.04 F:\WSL\ubuntu-backup.tar
wsl --import Ubuntu-22.04 F:\WSL\Ubuntu-22.04 F:\WSL\ubuntu-backup.tar --version 2
wsl -l -v          # 确认无误后再 wsl --unregister 旧发行版
```

> **vhdx 不会自动收缩**：在 WSL 里删掉源码后，Windows 侧看到的可用空间不会回来。
> 需要时先 `wsl --shutdown`，再用 `Optimize-VHD`（Hyper-V 模块）或 diskpart 压缩 vdisk。

### 内存与 CPU

全量编译建议 ≥ 12 GB 内存。在 Windows 用户目录建 `%USERPROFILE%\.wslconfig`：

```ini
[wsl2]
memory=12GB
processors=8
swap=8GB
```

改完 `wsl --shutdown` 才生效。机器是 16 线程时可把 `processors` 调到 12~16，
但内存不足时优先减 `RK_JOBS` 而不是加线程，否则 mke2fs 会被 OOM killer 杀掉。

## 2. WSL2 内的配置（关键）

源码工作区**必须**在 WSL2 原生 ext4（`/home/...`）里，**不能**放 `/mnt/e/...`：

| 问题 | drvfs（`/mnt/*`） | WSL2 ext4（`/home/*`） |
|---|---|---|
| 权限 / uid-gid / setuid | 全 777，不保留 | 正常 |
| 设备节点 mknod | 不支持 | 支持 |
| 大小写敏感 | 依赖 Windows 设置 | 正常 |
| 海量小文件 IO | 9P 协议，慢数倍 | 接近原生 |

`build-rootfs-img.sh` 要生成带 `/dev` 节点和 root:root 属性的 ext4 镜像，放在 drvfs 上会产出坏镜像。

```bash
# 在 WSL2 Ubuntu 里
cd /mnt/e/Projects/rk3528-sdk        # 只在 drvfs 上读取仓库（编辑方便）
cp config/sdk.wsl.conf.example config/sdk.local.conf
./rk3528-sdk.sh config               # 确认 4 个目录都指向 $HOME/rk3528-work/...
./rk3528-sdk.sh check-host --install
./rk3528-sdk.sh install-toolchain
./rk3528-sdk.sh status
```

> 仓库脚本本身留在 E 盘没关系（只是读几个 shell 文件），**所有源码、下载、产物、日志**由
> `sdk.wsl.conf` 指向 ext4。若希望连仓库也在 ext4，用 VS Code 的 Remote-WSL 打开
> `~/rk3528-sdk`，Windows 侧通过 `\\wsl$\Ubuntu-22.04\home\<user>\...` 访问。

产物取回 Windows：

```bash
cp -r ~/rk3528-work/out /mnt/e/Projects/rk3528-sdk/out/
```

## 3. 三条路线照常执行

```bash
# 路线 A：FriendlyWrt 全量
./rk3528-sdk.sh fw-init
./rk3528-sdk.sh fw-build all
./rk3528-sdk.sh fw-build emmc-img

# 路线 B：手工编译内核 / U-Boot
./rk3528-sdk.sh kernel-build
./rk3528-sdk.sh uboot-build

# 路线 C：sd-fuse
OS=ubuntu-noble-core-arm64
./rk3528-sdk.sh sdfuse-init "$OS" --with-eflasher
./rk3528-sdk.sh sdfuse-build kernel "$OS"
./rk3528-sdk.sh sdfuse-image sd "$OS"
```

脚本的 `require_linux` 在 WSL2 里会通过（`uname -s` = Linux），`require_not_root` 也满足
（WSL2 默认普通用户 + `sudo` 可用），`install-toolchain` 的 `sudo tar xf -C /` 正常。
不需要设置 `RK_ALLOW_NON_LINUX`（那只是给非 Linux 环境预演用的逃生开关）。

## 4. WSL2 特有的几个限制与检查

### loop 设备（影响 eMMC 卡刷固件）

WSL2 官方内核配置里 `CONFIG_BLK_DEV_LOOP=y`、`CONFIG_BLK_DEV_LOOP_MIN_COUNT=8`、
`CONFIG_EXT4_FS=y`，**内核层支持**。但 `/dev/loop*` 节点偶尔没建出来，先验证：

```bash
ls -l /dev/loop-control /dev/loop* 2>/dev/null
sudo losetup -f
```

若报找不到设备，试 `sudo modprobe loop` 或重启 WSL（`wsl --shutdown` 后重进）。

按上游脚本实际用法区分：

| 操作 | 是否需要 loop | WSL2 可行性 |
|---|---|---|
| 编译内核 / u-boot | 否 | 直接可用 |
| `build-rootfs-img.sh`（ext4，用自带 `mke2fs -d`） | 否 | 直接可用 |
| `mk-sd-image.sh`（普通 OS，用 `sd_update` 写 RAW 文件） | 否 | 直接可用 |
| `mk-sd-image.sh eflasher`、`mk-emmc-image.sh` | **是**（`losetup` + `mkfs.exfat`） | 通常可用，需上面的检查 |
| `FS_TYPE=btrfs` 的 rootfs 制作 | **是**（`mount -o loop`） | 通常可用 |

`mkfs.exfat` 来自 `exfatprogs`，本工具的 `check-host --install` 已包含该包；
若手动装依赖，记得 `sudo apt install exfatprogs`。

> 如果 eMMC 卡刷固件这一步在 WSL2 反复失败，最省事的做法是只产出 SD 启动镜像，
> 把 `emmc-img` 放到 CI 或另一台 Linux 机上做。

### 烧录必须回到 Windows 侧

微软文档明确：`wsl --mount` **不支持 USB 闪存驱动器 / SD 读卡器**（WSL issue #6011），
且 WSL2 默认内核没有启用 `CONFIG_USB_STORAGE`，直接 `usbipd-win` 直通 U 盘也看不到块设备。

| 场景 | 做法 |
|---|---|
| 烧写 SD 卡固件 | 把 `.img` 拷回 Windows，用 balenaEtcher / Win32DiskImager / Rufus |
| 线刷（loader / maskrom） | Windows 侧用 RKDevTool，或 `upgrade_tool` 的 Windows 版 |
| 开发板上 dd 更新分区 | 在**开发板**上跑 `install-board`，与 WSL 无关 |
| `sdfuse-image fuse` | 需要真实 `/dev/sdX` 块设备，WSL2 里不要用；改用 Windows 侧工具 |

### 其它

- **不要用 WSL1**：`wsl -l -v` 确认 VERSION 为 2。
- **大小写敏感**：WSL2 的 ext4 天然区分大小写；若把源码放 `/mnt/*`，需在 Windows 侧对目录执行
  `fsutil.exe file setCaseSensitiveInfo <path> enable`，但仍不解决 uid/gid 与 IO 问题，不推荐。
- **网络**：GitHub 访问不畅时按 [01-构建环境.md](01-构建环境.md) 设置
  `RK_GITHUB_MIRROR` / `RK_RAW_MIRROR`；WSL2 走 Windows 代理需指向 Windows 主机 IP。
- **systemd**：本工具不依赖 systemd，无需开启。
- **路径**：脚本里 `readlink -f`、GNU coreutils 在 WSL2 Ubuntu 下都是原生行为，无需改造。

## 6. 支持范围

本仓库**只支持以下两个平台**，其它环境不测试、不修兼容性问题：

| 平台 | 状态 | 说明 |
|---|---|---|
| **原生 Ubuntu 20.04/22.04/24.04 x86_64** | 支持 | 官方 README 的基准环境，见 [01-构建环境.md](01-构建环境.md) |
| **Win11 WSL2 + Ubuntu 22.04（24.04 亦可）** | 支持 | 本文 |
| WSL1 | 不支持 | `check-host` 直接拒绝；用 `wsl --set-version <distro> 2` 升级 |
| Windows 原生 Git Bash / MSYS2 | 不支持 | `require_linux` 会拒绝，且缺 ELF 工具链、loop 设备、ext4 语义 |
| macOS 原生 / Apple Silicon / arm64 Linux 主机 | 非目标 | 需另一套架构的预编译工具；本仓库不适配 |
| Docker 作为独立平台 | 非目标 | 本质是 Linux 环境，可直接套用上面的 Ubuntu 依赖清单，但不单独测试 |
| Ubuntu 18.04 | 不支持 | 缺 `lz4`，`check-host` 会拦截 |

脚本中保留的架构检测、镜像加速变量与预演开关属于通用实现细节，**不代表承诺支持上述非目标平台**。

> 路线 D（[W132D 主线 Linux](10-W132D主线Linux.md)）额外依赖 Docker 作为 Armbian 构建容器，
> 这是构建工具依赖、不改变上表；WSL2 下可用 Docker Desktop 的 WSL2 backend。
> 但 W132D 的 USB 刷写在 WSL2 下**未经上游验证**，建议用原生 Ubuntu 物理机执行。
